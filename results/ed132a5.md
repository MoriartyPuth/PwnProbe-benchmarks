## Regression check vs. PR 6

PR 6 (deterministic planner ranking) first reached the benchmark here. Every lab
that builds and whose class PwnProbe covers still recovers its flag, so the
reordering did **not** regress coverage. One expected ordering effect:

- `lab12_partial_overwrite` now wins via `stack_overwrite` instead of
  `partial_overwrite`. This is the intended PR 6 behaviour — cheaper, targeted
  strategies run before the deferred-expensive `partial_overwrite` — and the flag
  is still honestly recovered, so the harness counts it a pass with a strategy
  warning.

PR 7 is behaviour-preserving: same solved set, flags, and winning strategies as a
pre-PR-7 run on this host; it only adds the `context`/`verification` report
fields.

## Notes

- **lab07_ret2libc** — the strategy matches the leak by assuming it is
  `system()`'s runtime address (page-aligned base check). Under glibc 2.43 the
  leaked address does not align, so the strategy records 0 productive attempts
  and the lab is unsolved. Other session-based labs (lab05 shellcode, lab10
  canary) pass, so the session/executor path is fine — this is a libc-version
  sensitivity, not a code regression. A matching `--libc` would be the fix.
- **lab11_ret2syscall** — builds `-static`; this host has no static libc
  (`glibc-static`), so the link fails (`cannot find -lc`) and the lab is skipped.
  Install the static libc to run it.
- **gcc 16 / C23** makes implicit function declarations an error and `gets()` is
  undeclared, so the `gets`-based labs carry `-Wno-implicit-function-declaration`
  in their `build_flags`. The `gets` symbol still links in glibc 2.43, so no lab
  source changed.
- **Timings are host-specific and not comparable to `36acdbc`.** Several ROP labs
  run materially slower here (lab04 ~120s vs 16.8s; lab14 ~59s vs 6.4s; lab15
  ~424s vs 255.8s), while lab10 canary matches closely (~152s vs 148.8s). lab15
  needed a wall above the default 300s on this host. Set any numeric budget
  thresholds from numbers reproduced on the target host.
- `lab12_partial_overwrite` is **probabilistic** (one ASLR nibble); its time
  varies run to run.
- `lab13_angr_logic` used `PWNPROBE_PYTHON` (angr 10.0.5; unicorn fast-path
  disabled on this host, symbolic execution unaffected).

## Reproduce

```sh
git -C PwnProbes checkout ed132a5
( cd PwnProbes && go build -o bin/pwnprobe ./cmd/pwnprobe )
PWNPROBE_PYTHON=/path/to/angr-venv/bin/python \
  ./run.py --pwnprobe PwnProbes/bin/pwnprobe --wall 900 --out results/ed132a5.json
```

`lab11_ret2syscall` additionally needs a static libc (`glibc-static` on Fedora).
