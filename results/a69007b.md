## Notes

- `lab13_angr_logic` was run with `PWNPROBE_PYTHON` pointing at an angr (v10)
  virtualenv. Without angr the strategy is skipped and the lab reports unsolved.
- `lab10_canary_ret2win` and `lab11_ret2syscall` are the slow cases: both sweep
  padding/offset candidates over a fresh session per attempt, so their wall-clock
  time is dominated by connection setup, not computation.
- `lab12_partial_overwrite` is probabilistic (one unresolved ASLR nibble); the
  26.0s here will vary between runs.
- `lab07_ret2libc_intro` resolved offsets from this host's glibc 2.39. A target
  built against a different libc needs `pwnprobe solve --libc`.

## Reproduce

```sh
# build the solver from the tool repo at this commit
git -C PwnProbes checkout a69007b
( cd PwnProbes && GOOS=linux GOARCH=amd64 go build -o bin/pwnprobe ./cmd/pwnprobe )

# run the suite
PWNPROBE_PYTHON=/path/to/angr-venv/bin/python \
  ./run.py --pwnprobe PwnProbes/bin/pwnprobe --out results/a69007b.json
```
